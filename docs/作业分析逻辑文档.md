## 2. 信号配置

### 2.1 开口检测信号

| 设备 | 遥控信号 (remote) | 回转位置 (swing_pos) | 推进位置 (push_pos) | 推进压力 (push_press) |
|------|-------------------|---------------------|---------------------|---------------------|
| 东开口机 | LT_LQFC_57 | LT_LQFC_63 | LT_LQFC_67 | LT_LQFC_68 |
| 西开口机 | LT_LQFC_94 | LT_LQFC_100 | LT_LQFC_104 | LT_LQFC_105 |

> **remote** = 二进制信号（0=未选择 / 1=已选择开铁口机）  
> **swing_pos** = 回转角度值，正常范围 0~180°

### 2.2 堵口检测信号

| 设备 | 遥控启动 (remote_start) | 打泥指令 (mud_cmd) | 打泥位置 (mud_pos) | 打泥压力 (mud_press) |
|------|------------------------|--------------------|--------------------|---------------------|
| 东堵口机 | LT_LQFC_130 | LT_LQFC_134 | LT_LQFC_137 | LT_LQFC_138 |
| 西堵口机 | LT_LQFC_153 | LT_LQFC_157 | LT_LQFC_160 | LT_LQFC_161 |

> **remote_start** = 二进制信号（0=停止 / 1=遥控启动）  
> **mud_cmd** = 二进制信号（0=后退 / 1=打泥前进）

### 2.3 实际查询优化

- 周期检测阶段只查 **2 个必需信号**（开放口：remote + swing_pos；堵口：remote_start + mud_cmd）
- 其余 4 个信号已声明但当前未使用（预留后续阶段分析 / 指标提取）

## 3. 周期检测算法

### 3.1 开口作业检测

```
输入: 时间范围 [start, end]
输出: [{machine, type, window_start, window_end, duration_s}, ...]

对每台开口机:
  1. 查 InfluxDB 获取 remote + swing_pos 时序数据
  2. 遍历 swing_pos:

     ┌─ 状态: 待机 (in_cycle=False)
     │  条件: swing_pos 穿越 90° (如 89→91)
     │      且 remote 在 ±2s 内 ≥ 0.5
     │  → 记录 cycle_start，进入作业状态
     │
     └─ 状态: 作业中 (in_cycle=True)
        条件: swing_pos 反向穿越 90° (如 91→89)
        → 记录 cycle_end
        → 校验: 30s ≤ duration ≤ 3600s
        → 有效 → 生成周期记录
```

**关键参数：**

| 参数 | 值 | 说明 |
|------|-----|------|
| 穿越阈值 | 90° | 回转角度穿过 90° 视为开/关铁口动作 |
| 遥控容差 | ±2s | 遥控信号与回转信号的时间对齐窗口 |
| 最短周期 | 30s | 过滤误触发的噪声 |
| 最长周期 | 3600s (1h) | 过滤异常长时间区间 |

### 3.2 堵口作业检测

```
输入: 时间范围 [start, end]
输出: [{machine, type, window_start, window_end, duration_s}, ...]

对每台堵口机:
  1. 查 InfluxDB 获取 remote_start + mud_cmd 时序数据
  2. 遍历 mud_cmd:

     ┌─ 状态: 待机 (in_cycle=False)
     │  条件: mud_cmd 上升沿 (0 → 1)
     │      且 remote_start 在 ±2s 内 ≥ 0.5
     │  → 记录 cycle_start，进入作业状态
     │
     └─ 状态: 作业中 (in_cycle=True)
        条件: mud_cmd 下降沿 (1 → 0)
        → 记录 cycle_end
        → 校验: 30s ≤ duration ≤ 3600s
        → 有效 → 生成周期记录
```

### 3.3 辅助函数

```python

    """穿越阈值检测: (prev<thr 且 curr≥thr) 或 (prev>thr 且 curr≤thr)"""

    """在 target_ts ± tolerance 秒内是否存在遥控信号 ≥ 0.5"""
```

## 4. InfluxDB 查询策略

### 4.1 自适应降采样

查询窗口根据时间跨度自动选择，避免大范围查询超时：

| 时间跨度 | 聚合窗口 | 适用场景 |
|----------|----------|----------|
| ≤ 2 小时 | 10s | 单班次精细分析 |
| ≤ 8 小时 | 30s | 单班次快速扫描 |
| ≤ 24 小时 | 1m | 全天作业统计 |
| > 24 小时 | 5m | 多日趋势分析 |

### 4.2 Flux 查询模板

```flux
from(bucket: "islag")
  |> range(start: {start_utc}, stop: {end_utc})
  |> filter(fn: (r) => r._measurement == "DCS")
  |> filter(fn: (r) => r._field == "value")
  |> filter(fn: (r) => r.param == "LT_LQFC_57" or r.param == "LT_LQFC_63")
  |> aggregateWindow(every: {window}, fn: mean, createEmpty: false)
```

### 4.3 单例连接

- InfluxDBClient 全局复用
- 5 分钟自动重建，避免连接泄漏
- 线程安全（双重检查锁）

## 5. 时间格式归一化

前端 `<input type="datetime-local">` 发送格式：`2026-07-03T00:00`（无秒、无时区）

Flux `range()` 要求 RFC3339 格式：`2026-07-03T00:00:00Z`

```python
def _normalize_time(time_str):
    """2026-07-03T00:00  →  2026-07-03T00:00:00Z"""
```

| 输入格式 | 输出格式 | 触发场景 |
|----------|----------|----------|
| `2026-07-03T00:00` | `2026-07-03T00:00:00Z` | 前端未带秒 |
| `2026-07-03T00:00:00` | `2026-07-03T00:00:00Z` | 有秒无时区 |
| `2026-07-03T00:00:00Z` | 保持不变 | curl 测试 |

## 6. 数据持久化

### 6.1 cycles 表 (SQLite)

```sql
CREATE TABLE cycles (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    equipment_id  TEXT NOT NULL,        -- "东开口机" / "西堵口机"
    cycle_type    TEXT NOT NULL,        -- "opening" / "plugging"
    start_time    TEXT NOT NULL,        -- ISO 8601 UTC
    end_time      TEXT NOT NULL,        -- ISO 8601 UTC
    duration_s    REAL,                 -- 作业时长 (秒)
    confidence    REAL DEFAULT 0.0,     -- 检测置信度
    created_at    TEXT DEFAULT datetime('now')
);
CREATE INDEX idx_cycles_equipment ON cycles(equipment_id, start_time);
```

### 6.2 去重策略

每次检测完成后，与已有记录比对 `(equipment_id, cycle_type, start_time)` 三元组，已存在则跳过。

> 当前 `confidence` 固定为 0.8，后续可由规则引擎或模型评分更新。

## 8. 前端交互流程

```
1. 用户选择时间范围、设备、作业类型
2. 点击「开始分析」
3. 前端发送 GET /api/analysis/cycles
4. 等待响应 → 遮罩层显示 "正在检测作业周期..."
5. 接收数据:
   - 有周期 → 渲染表格 (设备/类型/开始/结束/耗时) + 统计卡片
   - 无周期 → 显示 "未检测到作业周期"
6. 检测到的周期自动写入 SQLite
7. 进入「循环标注」页面可查看和标注
```
